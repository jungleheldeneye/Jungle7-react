# 요구사항

## 배경
기존에는 데이터가 바뀔 때마다, 그 데이터를 보여주는 화면 요소를 개발자가 직접 찾아서 하나하나 고쳐줘야 했다.
하나라도 빠뜨리면 화면과 데이터가 어긋나고, 그렇다고 화면 전체를 다시 그리면 느리고 사용자 입력이 사라진다.

## 요구사항

| ID | 요구사항 | 해결 | 우선순위 |
| --- | --- | --- | --- |
| R1 | 데이터만 바꾸면 화면이 자동으로 일관되게 따라온다 | setState | Must |
| R2 | 화면은 "데이터가 이럴 때 이렇게 생겼다"만 기술하면 된다 | 컴포넌트 = 함수 | Must |
| R3 | 다시 그려도 빠르고 사용자 입력이 유지된다 | VDOM + Diff + Patch | Must |
| R4 | 화면을 재사용 가능한 조각으로 나눠 만들 수 있다 | 컴포넌트 + props | Must |
| R5 | 데이터가 어디에 있고 어디서 바뀌는지 예측 가능하다 | Lifting State Up | Must |
| R6 | 렌더 후 필요할 때만 화면 밖 작업(side effect)을 실행한다 | useEffect | Must |
| R7 | 바뀐 게 없으면 계산을 재사용한다 | useMemo | Must |
| R8 | 리스트 순서가 바뀌어도 최소한으로 갱신된다 | key | Should |
| R9 | 여러 상태 변경을 한 번의 렌더로 묶는다 | Batching | Could |

## 제약
- Vanilla JS, 외부 프레임워크 금지
- state와 hook은 루트 컴포넌트에서만, 자식은 props만 받는 순수 함수
